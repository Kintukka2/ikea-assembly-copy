## This is Next.js 16

This version has breaking changes: APIs, conventions and file structure may differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code, and heed deprecation notices. (`agentRules: false` in `next.config.ts` keeps `next dev` from rewriting this file.)

## House rules

- No em dashes or en dashes anywhere: copy, code, comments, commit messages. Use a comma, colon or parentheses.
- One voice only: Kokoro `af_heart`, on Together AI for live lines and `scripts/voice/record.ts`, or the same model run locally by `scripts/voice/local.ts` (`src/lib/voice/tts.ts`). Never fall back to the device's speech.
- IKEA's raw listings (`scripts/ikea/facts*.json`, `scripts/ikea/cache/`) stay out of git; only the rows built from them in `src/data` ship.
- Every guide is generated by `src/lib/plan` and follows the product's own assembly manual, IKEA's or Kmart's: the same steps in the same order, with the same parts, fittings and counts. Draw and word everything ourselves; the shops' drawings, photos and text are copyrighted, so never copy them into the app.

## Brands

- Everything brand specific lives in `src/lib/brands.ts`: name, owner, how it numbers products, where its manual is, the disclaimer. Add a shop there first.
- A shop's catalog rows live in `src/data` (`kmart.ts` for Kmart); slugs other than IKEA's start with the brand (`kmart-8-cube-storage-unit`) and never change once shipped.
- A family recipe for a shop other than IKEA is keyed `"<BRAND>:<LINE>"` (`"KMART:CUBE STORAGE"`) in `src/lib/plan/families/<brand>-<line>.ts`; IKEA's stay keyed by the first word of the name. Use the manual's own part numbers as labels.
- `npm run kmart:check` builds every Kmart guide and prints it step by step; `npm run ikea:check` does the same for IKEA's catalog.
